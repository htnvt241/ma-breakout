# 均線發散突破（台股）

每天自動找出符合「均線發散突破」的台股上市＋上櫃普通股，列出訊號清單、K 線圖與事後報酬統計。

網站：https://htnvt241.github.io/ma-breakout/

## 訊號定義

同一天以下三個條件都成立，就算一個訊號（全部用**還原收盤價**計算）：

1. **均線多頭排列**：20MA > 60MA > 120MA
2. **突破**：收盤價 > 前 10 個交易日（不含當天）的最高收盤價
3. **均線上揚且發散**：5MA、10MA、20MA 的「5 日變化」都 > 0，而且 5MA 的變化最大
   - 「nMA 5日」＝今天的 nMA ÷ 5 個交易日前的 nMA − 1

訊號分類：

| 類型 | 定義 |
|---|---|
| 首次 | 同一檔前 10 個交易日內沒有出現過訊號 |
| 再次 | 前 10 個交易日內出現過訊號、中斷後當天再度符合 |
| 連續 N 天 | 前一個交易日也符合；N＝到當天為止連續符合的天數 |

訊號後的報酬（還原收盤價）：

- +5／+10／+20 日：第 N 個交易日的收盤 ÷ 訊號日收盤 − 1（還沒走完的顯示「—」）
- 至今報酬：最新收盤 ÷ 訊號日收盤 − 1
- 至今最高／最低：訊號**隔天**到最新收盤日之間的最高／最低收盤
- 同期 0050：同一段日期 0050（還原）的報酬，用來對照大盤
- 成交額：訊號日收盤價 × 成交量（不設門檻）

規則寫在 `scripts/signals.py`，改規則時要一起改這份 README 和網頁下方的說明。

## 整體統計列

依網頁上目前的篩選條件（日期區間、類型、市場、搜尋）即時計算，只計入已經走完該天數的訊號：
樣本數、平均報酬、中位數、勝率（報酬 > 0 的比例）、同期 0050 平均、超額（平均 − 0050 平均）。

## 資料來源

- **股票清單、產業別、上市櫃日**：臺灣證券交易所 ISIN 公開資料（`isin.twse.com.tw`），取「股票」區段 4 位數代號的普通股，上市（含創新板）＋上櫃，排除 ETF、TDR、特別股。這個網站很慢（約 14 分鐘），所以一天只抓一次（當天第一次執行），同一天其他次沿用；抓不到時沿用前一版網站的清單。
- **興櫃時期**：Yahoo 的歷史資料會包含股票上市櫃之前的興櫃交易（沒有漲跌幅限制）。**上市櫃日之前不算訊號**、也不做漲跌檢查；價格仍保留給 K 線圖與均線使用。
- **價格**：Yahoo Finance chart API（日 K 與還原收盤價），上市用 `.TW`、上櫃用 `.TWO`（找不到會試另一個）。
  - K 線圖的開高低收都用「還原權值」換算，所以和實際成交價可能不同；清單的「收盤」欄是 Yahoo 的收盤價（已含分割調整，未含除息）。
  - 成交量為 0 且開高低收都一樣的日子視為沒有交易（停牌、颱風假），不列入。
  - 執行時如果當天還沒收盤（Yahoo 給的是盤中價），當天資料會去掉。
- **官方資料修正**（`scripts/official.py`）：用證交所、櫃買中心的官方每日收盤行情修正 Yahoo：
  1. Yahoo 整個市場都缺的平日 → 查官方，有交易就把當天全部股票補進去（還原係數用後一天的）；官方說沒交易就記成假日，以後不再查。
  2. 被標成可疑漲跌的日子（和前一天）→ 和官方收盤比對，差超過 1% 就換成官方的開高低收量。
  - 官方一個檔案就是當天全部股票，抓過的存在網站的 `data/official.json`，下次沿用；每次最多花 25 分鐘抓，沒抓完的下次繼續。
  - 證交所會擋太密集的請求，每個請求間隔約 3 秒。
  - 修了哪些、還剩哪些可疑漲跌（以及官方是否也是同樣價格），都列在網站最下方「資料檢查」。
- **交易日曆**：超過三成股票有成交的日子才算交易日（只看單一檔，遇到 Yahoo 漏資料會出錯）。
- **大盤基準**：0050（還原）。

已知限制：股票池只有「目前」還上市櫃的股票，期間內下市的不在內（倖存者偏差），報酬統計可能略為偏高。

## 自動更新與安全機制

GitHub Actions（`.github/workflows/build.yml`）每個交易日台灣時間 14:47、16:23、18:41 各跑一次，也可以在 Actions 頁面手動按「Run workflow」。

每次都是**從頭重新產生整個網站**，產生成功才發布（GitHub Pages 的部署），**不會把資料存進 git 紀錄**，所以 repo 不會一直變大。

以下狀況這次**不發布**，網站維持前一版，並開 Issue 通知（GitHub 會寄 email）：

- 0050（交易日曆）抓不到
- 抓到新資料的股票不到 90%
- 這次的最新交易日比網站上的還舊
- 股票清單抓不到、前一版也沒有

個別股票抓不到時，沿用前一版網站上該股票的資料，並記在「資料檢查」。

## 資料保留（每月滾動 5 年）

- 訊號只保留「本月 1 日往前 60 個月」以內，而且不早於 2022-01-01。例如 2027 年 2 月起算日是 2022-02-01。
- 價格資料另外多留 13 個月在起算日之前，給 120MA 暖機和 K 線圖畫「訊號前約 60 個交易日」用，這段不會出訊號。
- 因為每次都整個重新產生，超過期間的資料下次產生時就自然不見；如果那次產生失敗，舊網站（含舊資料）會原封不動保留。
- 選每月而不是每天：每天挪的話，統計數字每天都會因最舊的訊號掉出而小幅變動；每年挪一次則最多會留到將近 6 年。

設定在 `scripts/build_data.py` 開頭：`START_FLOOR`、`KEEP_MONTHS`、`PX_BUFFER_MONTHS`。

## 資料檢查

網站最下方「資料檢查」可以看到：

- 抓到新資料的檔數、沿用舊資料的股票、完全抓不到的股票
- **單日漲跌超過 ±10.5%**：台股漲跌幅上限是 10%，超過通常代表資料錯誤（例如還原價出錯）。和前一筆資料之間缺了交易日（停牌、零成交或 Yahoo 漏資料）時，上限按天數複利放寬（缺 1 天約 ±21%），因為那其實是兩天的漲跌。已排除新上市前 5 天、停牌 3 天以上恢復交易後的前 5 天（這些日子沒有漲跌幅限制）。
- 0050 在 Yahoo 缺少的交易日（這些日子開始或結束的訊號，「同期 0050」會空白）
- 最新交易日沒有成交的股票（可能停牌）
- 期間內缺少交易日的股票（多半是停牌）

只有「這次新出現」的問題（最近 5 個交易日新出現的異常漲跌、新出現抓不到的股票）才會開 Issue，避免同一個問題每天寄信；問題消失後下一次正常更新會自動關閉 Issue。

## 檔案

| 路徑 | 說明 |
|---|---|
| `scripts/signals.py` | 訊號規則與報酬計算 |
| `scripts/build_data.py` | 抓資料、安全檢查、產生網站 |
| `scripts/check_report.py` | 產生 Issue 通知內容 |
| `scripts/make_mock.py` | 產生本機測試用假資料 |
| `site/` | 網頁（`index.html`、`app.js`、`chart.js` 自製 K 線圖、`style.css`） |

產生後的網站資料（`_site/data/`）：`meta.json`（摘要、0050 價格）、`stocks.json`（股票清單）、`signals.json`（全部訊號）、`px/<代號>.json`（每檔 K 線）、`check.json`（資料檢查）。

本機測試（不連網）：

```
python scripts/make_mock.py /tmp/mock
MOCK_DIR=/tmp/mock python scripts/build_data.py
cd _site && python -m http.server
```
